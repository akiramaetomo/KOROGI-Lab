# KOROGI-Lab — 公開設計

## 音声経路

各Timbreは`ChannelSynth`が音源、変調、フィルタ、AEnv、BURST、FX1を所有します。FX1後のステレオ信号へLevel、Mute、Pan、Near／Far送信を適用し、8枠を共有バスへ加算します。Near／Farは独立したFX2→FX3→Bus Gainを通り、Output Balance、Master、Limiterへ合流します。

図のMON経路は選択TimbreのFX1後をMasterへ送りますが、通常のCOMMON SPACE処理も継続して残響状態を保持します。表示中の信号線と実際の音声経路を一致させます。

## 時刻と所有権

音声時刻は`AudioContext.currentTime`を基準とします。Manual Gate、Auto scheduler、User Pattern transport、BURST schedulerは発音所有者を分離し、別の所有者の停止で保持中Manual Gateを切らない構造です。

Play Allは共通開始時刻を渡します。User Patternの区間変更は次の周回境界から適用し、停止時は対象枠の未開始予約を取り消します。Gate ON時のAEnv、PEnv、位相設定は、そのGateのsnapshotとして扱います。

## UIと永続化

UIは8枠の概要と選択Timbreの詳細を分離します。Signal MapはDOMノードの矩形からSVG配線を計算し、resizeと内部スクロールに追従します。

JSONは読込時に構造検査と正規化を完了してからライブ状態へ適用します。MONなど一時的な監視状態は保存しません。Demo Sessionも通常のSession parserと適用境界を共有します。
