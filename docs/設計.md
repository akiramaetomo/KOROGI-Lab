# KOROGI-Lab — 公開設計

## 音声経路

各Timbreは`ChannelSynth`が音源、変調、フィルタ、AEnv、AEnv2、BURST、FX1を所有します。OSCは`SourceUnit`が成分（partial）の集合として持ち、Base・PEnvの周波数バスを成分ごとの比のGainを経て各`OscillatorNode`へ入れ、cent経路（Detune、FM、Sequence Pitch）は全成分のdetuneへ同じ信号を入れます。2系（OSC2→Filter2）は、MOD・F1 cutoff・AEnv IN・AEnv OUTの経路ゲインのうち選択中の1つだけを10 msで開きます。AEnv2はAEnv1と同じGate・取消・BURSTの配送を受け、AEnv OUTのときだけ出力されます。FEnvはFilter1へ直接、Filter2へはDepthのGainを経てdetuneに入ります。FX1後のステレオ信号へLevel、Mute、Pan、Near／Far送信を適用し、8枠を共有バスへ加算します。Near／Farは独立したFX2→FX3→Bus Gainを通り、Output Balance、Master、Limiterへ合流します。

図のMON経路は選択TimbreのFX1後をMasterへ送りますが、通常のCOMMON SPACE処理も継続して残響状態を保持します。表示中の信号線と実際の音声経路を一致させます。

## 時刻と所有権

音声時刻は`AudioContext.currentTime`を基準とします。Manual Gate、Auto scheduler、User Pattern transport、BURST schedulerは発音所有者を分離し、別の所有者の停止で保持中Manual Gateを切らない構造です。

Loop（内部名Play All）は共通開始時刻を渡します。Patternの区間変更は次の周回境界から適用し、停止時は対象枠の未開始予約を取り消します。Gate ON時のAEnv、PEnv、位相設定は、そのGateのsnapshotとして扱います。

時間方式はSession共通の`SongSettings.timingMode`です。Barsの伸縮は`model/stretch`が基準Pattern、Pattern長、ループ秒、倍率（選択区間長÷ループ長）を計算し、`model/metronome`が1小節の格子、次の小節頭、クリック時刻を与えます。録音も同じ倍率の録音時計で周回し、入力を記録秒へ戻して保存します。

Chain（内部名Song）の`SongTransport`は、SONG格子でONかつGate記録のある番号から区間列を作り、AudioContext時刻で予約します。Barsの区間長は`model/songFrame`のFrame長で決まり、各PatternはPattern長でループして区間末で切れます。再生中の変更は、Pitch設定なら区間内の位相を保って即時に作り直し、記録や長さの変更なら次の区間の頭で作り直します。BPM変更時は現在位置を保って将来予約を更新します。通常のSequenceTransportとは再生時計を分離します。

再予約・取消され得るAudioParamには`setValueCurveAtTime`を使いません。Logarithmic PEnvは同じ点を結ぶ短い線形ランプで予約します（ChromeでValueCurveの取消が残骸を残し、Song中のBPM変更でハングしたため）。

レーンのMuteは時計を止めず、出力側だけを切ります。Gateは予約時にONイベントを落とし、Pitchはdetune／Filterへのgainで切り離すため、解除するとその時点の位相から復帰します。OSC／Filterの構造変更は項目ごとに最新の要求だけを残し、共有フェード1周期で保留中の全項目を確定します。

Gateクオンタイズは`quantizeGateRecording`が記録済みGate列から新しい列を作る純粋な変換で、Undo／Redoは直前1操作の列を保持します。Separate中のコントローラは、レーンごとの入力所有者を切り替え、解放時に記録・Auto・Songの現在位置へ戻します。

## UIと永続化

UIは8枠の概要と選択Timbreの詳細を分離します。Signal MapはDOMノードの矩形からSVG配線を計算し、resizeと内部スクロールに追従します。エディットのカード配置は`editorLayout`が列ごとの積み枚数（最大3）と追加位置の規則を持ち、保存時の配置もこの規則で検査します。

SONG格子のセル状態は`model/songArrangement`、表示は`ui/SongArrangement`が持ち、セルの選択はTimbreカードの選択と違ってエディタのカード構成を変えません。Patternコピーは`model/patternCopy`がPattern長の引き継ぎを計画します。

JSONは読込時に構造検査と正規化を完了してからライブ状態へ適用します。旧SessionのPattern長は旧Pattern共通小節数から、Frame長はChainに入る番号の最大値から移行します。MONなど一時的な監視状態は保存しません。Demo Sessionも通常のSession parserと適用境界を共有します。
